> 版本：1.0

> 项目：Paddy

## 1. 产品概述

### 1.1 背景

好雨粮库每日约有 100 车原粮进厂扦样作业。传统方式依靠人工登记和口头协调，效率低且容易混乱。需要一个轻量的手机H5系统来管理预约、排队、扦样全流程。

### 1.2 目标

- 司机端可通过手机H5页面提前预约进厂扦样时间，避免现场排队等待
- 管理员在PC端统一管理预约列表，分配令牌、录入扦样结果
- 排队叫号功能保证粮库扦样有序进行
- 好雨粮库管理者手机H5页面可快捷查看当日作业概况数据

### 1.3 非目标

- 不涉及地磅称重数据接入
- 不涉及财务结算
- 不涉及多粮库/多租户支持
- 支持手机端H5, 司机端预约、排队，管理者通过手机H5页面可快捷查看当日作业概况数据
- 支持PC 端，管理端页面在 PC 宽屏下布局，管理端主要用在PC端
- 支持一次开发、多端使用
- uniapp 技术支持

## 3. 功能需求

### 3.1 预约管理

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| FR-01 | 创建预约 | 司机填写姓名/手机/车牌/品种/日期/时间，提交后系统自动生成预约编号 | P0 |
| FR-02 | 查询记录 | 司机通过手机号+预约编号查询历史记录和扦样结果 | P0 |
| FR-03 | 分配令牌 | 操作员为预约分配令牌号，状态转为 token_assigned | P0 |
| FR-04 | 预约列表 | 操作员和好雨粮库管理者均可查看所有预约，支持状态筛选、关键词搜索、分页加载 | P0 |
| FR-05 | 取消预约（司机） | 司机在通知页取消自己的 pending 预约，原因可选 | P0 |
| FR-06 | 取消预约（操作员） | 管理员取消任意状态预约，waiting 时自动出队，原因必填 | P0 |

### 3.2 排队叫号

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| FR-07 | 签到入队 | 操作员确认司机到场后点击"签到入队"，进入 waiting 状态 | P0 |
| FR-08 | 排队看板 | 操作员查看当前等待队列，支持叫号/跳过/取消排队操作 | P0 |
| FR-09 | 排队状态 | 司机查看自己当前位置、前方等待人数，30s HTTP 轮询刷新，首次加载立即刷新 | P0 |
| FR-10 | 叫号通知 | 司机被叫号时页面显示通知（轮到你了，请前往扦样区） | P0 |
| FR-11 | 自动叫下一号 | 扦样录入完成后自动从 waiting 队列中叫下一个 | P1 |

### 3.3 扦样录入

| ID | 功能 | 描述 | 优先级 |

| FR-13 | 数据校验 | 水分范围 12%-20%，出米率范围 55%-65%，超出范围拒绝提交 | P0 |

## 4. 状态模型

### 4.1 预约状态流转

```
pending         →   预约提交成功，等待管理员处理
token_assigned  →   管理员已分配令牌号，等待签到入队
waiting         →   司机已签到，在排队队列中等待叫号
called          →   已被叫号，司机可前往扦样区
completed       →   扦样结果已录入，流程结束
cancelled       →   预约已取消（司机或管理员操作）
```

### 4.2 流转规则

| 当前状态 | 允许操作 | 目标状态 | 操作角色 |
|----------|----------|----------|----------|
| pending | 分配令牌 | token_assigned | 操作员 |
| pending | 取消 | cancelled | 司机/管理员 |
| token_assigned | 签到入队 | waiting | 操作员 |
| token_assigned | 取消 | cancelled | 操作员 |
| waiting | 叫号 | called | 操作员 |
| waiting | 跳过 | waiting (队尾) | 操作员 |
| waiting | 取消排队 | token_assigned | 操作员 |
| waiting | 取消 | cancelled | 操作员 |
| called | 录入结果 | completed | 操作员 |
| called | 取消 | cancelled | 操作员 |

## 7. 非功能需求
